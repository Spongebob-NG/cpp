在 Linux x86-64 架构下，CPU 拥有 16 个 64 位的通用寄存器（General Purpose Registers, GPRs），以及指令指针和标志寄存器。



它们并不是杂乱无章的，而是在工业界通行的 **System V AMD64 ABI（Linux 标准调用约定）** 规范下，分工极其明确。在排查系统崩溃（Core Dump / Kernel Panic）、手写汇编优化、或者写探针/eBPF 抓取内核现场时，这些寄存器的职责是工程师的必备内功。



这些关键寄存器可以系统性地归纳为五大阵营：



**一、 函数传参“六剑客”（Function Arguments）**



在 32 位系统时代，C 语言传参全靠压栈（Push 内存栈），效率很低；而 64 位系统确立了“寄存器传参优先”的黄金法则。调用任何 C/C++ 函数或系统调用时，前 6 个入参严格按以下顺序装载进指定寄存器：



| **寄存器名称**   | **历史英文原义**               | **在现代 Linux 传参中的核心分工**                            |
| ---------------- | ------------------------------ | ------------------------------------------------------------ |
| **`RDI`** (`di`) | Destination Index（目的变址）  | **函数的第 1 个入参**。如 `sys_execve(pathname, ...)` 中的 `pathname` 指针就是它。 |
| **`RSI`** (`si`) | Source Index（源变址）         | **函数的第 2 个入参**。如 `sys_execve(..., argv, ...)` 中的 `argv` 数组指针就是它。 |
| **`RDX`** (`dx`) | Data Register（数据寄存器）    | **函数的第 3 个入参**。如 `sys_execve(..., envp)` 中的 `envp` 环境变量指针。在通用计算中也常配合乘除法存放高位数据。 |
| **`RCX`** (`cx`) | Counter Register（计数寄存器） | **函数的第 4 个入参**。在底层循环指令（如 `rep movsb` 或 `loop`）中，它天然充当递减计数器（`for` 循环中的 `i`）。 |
| **`R8`**         | Register 8（通用寄存器 8）     | **函数的第 5 个入参**。                                      |
| **`R9`**         | Register 9（通用寄存器 9）     | **函数的第 6 个入参**。                                      |

> **注**：如果一个函数的参数超过 6 个（例如第 7、第 8 个参数），寄存器不够用了，编译器才会妥协将超出的部分通过用户栈（Stack）压栈传递。

**二、 成果汇报与系统调用枢纽（Return Value & System Call）**



- **`RAX`（Accumulator Register，累加寄存器）**：
  - **职责 1：存放函数返回值**。一个普通 C/C++ 函数返回的 `int`、指针或对象地址，在汇编层面都是由被调函数塞进 `RAX`，调用方直接去 `RAX` 里取结果。在 `kretprobe` 中捕获函数成功与否，看的正是 `regs->ax`。
  - **职责 2：系统调用编号（Syscall Number）**。当用户态执行 `syscall` 指令陷入内核时，CPU 靠 `RAX` 里存的数字来判断到底要调用什么（例如在 x86-64 下，`RAX=0` 是 `sys_read`，`RAX=1` 是 `sys_write`，`RAX=59` 是 `sys_execve`）。
- **`orig_ax`（仅存在于 Linux 内核 `pt_regs` 里的特殊字段）**：
  - 当发生系统调用时，内核会先把当时传进来的系统调用号（`RAX` 的原始值）备份进 `orig_ax`。因为进入系统调用处理逻辑后，`RAX` 马上就要被用来临时存放计算中间值或最终返回值。内核为了排查“最初到底调的是哪个系统调用”，专门留了这块记忆。

**三、 内存栈管理双雄（Stack Frame Management）**



每个线程在内存中都有一根向下增长的“执行栈”（用户栈或内核栈），用来存放局部变量和返回地址。管理这根栈由两个核心寄存器死死扣住：



- **`RSP`（Stack Pointer，栈顶指针寄存器）**：
  - **永远指向当前栈的最末尾（地址最低处的栈顶）**。
  - 执行 `push` 指令时，`RSP` 自动减 8 字节并写入数据；执行 `pop` 指令时，读出数据且 `RSP` 自动加 8 字节。一旦 `RSP` 发生非法的巨大偏移，就会直接导致 Stack Overflow（栈溢出）。
- **`RBP`（Base Pointer，栈基址/帧指针寄存器）**：
  - **指向当前函数调用栈帧（Stack Frame）的底部**。
  - 传统 C/C++ 函数调用时，进入函数第一件事就是把上一层函数的 `RBP` 压栈，然后把当前 `RSP` 赋给 `RBP`（即经典的 `push %rbp; mov %rsp, %rbp`）。
  - **核心价值**：它是调试器（GDB）和内核打印函数调用回溯（Backtrace / Call Stack）的绳索。顺着每个栈帧保存的旧 `RBP` 一层层往上倒推，就能还原出 `main() -> foo() -> bar()` 的完整调用链路。

**四、 指令大脑与状态标志（Execution Control）**



- **`RIP`（Instruction Pointer，指令指针寄存器）**：
  - **CPU 最核心的心脏。它永远存放着“CPU 即将执行的下一条机器指令的内存虚拟地址”**。
  - 正常情况下 CPU 执行一条指令，`RIP` 就自动向前跳几字节；
  - 执行 `jmp`、`call`、`ret` 时，本质上就是把目标代码地址强行覆盖进 `RIP`，驱使 CPU 转向新代码。
  - 在探针中：kprobe 就是在目标内存处改了指令触发中断，此时捕获到的 `regs->ip` 精准告诉了你 CPU 究竟是在哪行汇编处被你抓到的。
- **`RFLAGS`（Flags Register，标志寄存器）**：
  - 它不是用来存指针或数值的，而是**以每一位（Bit）为单位，记录 CPU 上一次算术/逻辑运算的结果状态**：
    - **ZF（Zero Flag，零标志位）**：上一步运算结果是否为 0。C 语言里的 `if (x == 0)` 底层汇编是 `cmp` 指令，如果相等，CPU 自动把 ZF 置为 1，随后 `je`（Jump if Equal）指令根据 ZF 是否为 1 来决定要不要跳转。
    - **CF / OF（进位标志 / 溢出标志）**：无符号数或有符号数运算是否发生高位溢出。
    - **IF（Interrupt Enable Flag，中断允许位）**：控制当前 CPU 核心是否允许接收外部硬件中断。在内核关中断临界区，通过 `cli` 汇编指令将此位清零，所有外部设备硬件中断全部被屏蔽。

**五、 算力扩展与通用杂役寄存器（Scratch & Callee-saved）**



x86-64 相比老 32 位架构额外新增了 8 个以数字命名的通用寄存器（`R8` ~ `R15`），加上经典的 `RBX`、`R10`、`R11`：



- **`RBX`（Base Register，基址寄存器）**：
  - 通用数据暂存寄存器，通常用来计算复杂的内存基地址。
- **`R10` 与 `R11`**：
  - **`R10` 的关键特殊职责**：在发起 `syscall` 系统调用时，CPU 硬件指令会霸占 `RCX`（硬件用来保存用户态的 `RIP`）。所以**在发起系统调用传参时，第 4 个参数不走 `RCX`，而是走 `R10`**。
  - **`R11`**：系统调用时，CPU 硬件专门用它暂存用户态的 `RFLAGS`。
- **`R12` ~ `R15`**：
  - 纯粹的高性能临时运算扩展槽，供编译器把深层循环里的局部密集变量塞进去，避免频繁访存。

**六、 进阶认知：调用者保存 vs 被调用者保存（ABI 铁律）**



在汇编和内核开发中，这 16 个寄存器还被严格划分为两大“责任阵营”，这对理解探针行为至关重要：



1. **调用者保存（Caller-saved / Scratch Registers，即用即扔）**：
   - 包含：`RAX`、`RCX`、`RDX`、`RSI`、`RDI`、`R8`、`R9`、`R10`、`R11`。
   - **规则**：一个函数如果调用了别的函数，**被调函数有权随意蹂躏、篡改这些寄存器的值**。如果主调函数后续还要用，必须在调函数前自己把它们压栈保存在内存里。
2. **被调用者保存（Callee-saved / Preserved Registers，用完必须复原）**：
   - 包含：`RBX`、`RBP`、`RSP`、`R12`、`R13`、`R14`、`R15`。
   - **规则**：任何函数只要用到了这几个寄存器，**在退出函数（执行 `ret`）前，必须通过 `pop` 把它们的值完全恢复成进入函数前的原样**。如果没恢复，调用者拿到被污染的寄存器就会立刻逻辑崩溃。
