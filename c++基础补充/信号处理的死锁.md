#### 信号处理的死锁

###### 存在原因

printf、malloc、free等标准库函数为了**保证多线程安全** **内部都在维护一个共享状态** 并且会**加锁**来维护它  比如printf维护全局stdout文件流缓冲区（避免多线程输出内容错乱） malloc/free维护堆内存分配链表 等   如果执行流本身在这些非异步信号安全函数里面，比如正在使用printf函数，会拿到锁，这个时候来了异步信号处理，其中也调用printf函数的话 就会发生**死锁** （中断跟信号的原理一样）

###### 如何解决

在linux系统编程里面 函数被严格划分为两类

1. **非异步信号安全函数** 内部会涉及加锁/操作全局静态变量/动态内存分配  如printf、sprintf、malloc、free、new、delete、exit 以及绝大部分STL容器（**内部都有动态扩容或内存操作**）
2. **异步信号安全函数** 只操作栈上私有局部变量 或者直接调用原子的、可重入的系统调用 如write()、read()、open()、close()、_exit()  因为这些都没有缓冲区

所以为了避免信号死锁  就必须只能在**信号处理函数**里面**使用异步信号安全函数** 

或者使用**原子变量**来设定一个标志位  **非异步信号安全函数只在main函数中使用** 

```c++
#include <atomic>
#include <unistd.h>

// 严格使用 sig_atomic_t 或 std::atomic
std::atomic<bool> g_shutdown_requested{false};

void clean_sig_handler(int sig) {
    // 安全操作 1：使用底层无锁系统调用输出调试信息
    const char msg[] = "Signal received\n";
    write(STDERR_FILENO, msg, sizeof(msg) - 1);

    // 安全操作 2：仅修改原子标志位，立即返回
    g_shutdown_requested.store(true, std::memory_order_relaxed);
}

// 主线程死循环中检测该标志，在主流程安全上下文中进行常规的资源释放与 printf
```
