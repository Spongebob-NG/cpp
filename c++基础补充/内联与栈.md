#### 内联与栈

##### 栈

###### 详解

1. 线程在内核创建时只分配一段连续虚拟内存（linux默认8MB） **函数调用链、返回地址、控制流上下文与局部变量完全共用同一个物理栈**

2. **内存**本质上是**RAM** 所以是**支持任意随机寻址**的！所谓的**后进先出是数据结构宏观上的**  比如说计算d=a+b+c，不需要把c弹出来才能拿a 可以直接像查数组下标一样**抓取栈内的任意字节** 因为编译器在编译期就为每个局部变量定死了**相对于栈基址的固定偏移**

3. **函数调用与返回的硬件级全流程**

   ```c++
   进入函数：
   1.传参  优先使用寄存器传参 超出的部分压栈
   2.call指令  将下一条指令的地址（返回地址）压入栈顶 跳转至目标函数地址 （这里说的指令是调用者调用完函数之后的下一条指令）
   3.建立栈帧  先保存上一个函数的栈底地址（压栈） 把当前的基准点设置成之前的栈顶  然后栈顶向下移动N个字节 一次性划出局部变量要的空间
   4.退出函数  先回收栈空间，也就是将栈顶直接拉回基准点 瞬间把所有局部变量作废。 然后将之前压栈的老基准点弹回寄存器 恢复调用者的栈底  最后ret指令从当前栈顶弹出返回地址给CPU的指令寄存器 程序调回调用者继续执行代码
   ```
   
4. **变量销毁**

   ```c++
   1.内置基本类型（平凡类型）
   销毁：仅靠移动栈顶指针
   内存残留与野值：硬件不会主动将栈内存清零，会空耗CPU时钟周期，所以未初始化的局部变量沿用的是上一个在此处执行的函数遗留的栈内存脏数据
       
   2.非平凡c++对象
       双层结构：对象本身的元数据（指针 容量 大小等）在栈上，管理的真实数据在堆上
   析构：在移动栈顶指针之前 先严格按照构造的相反顺序一次调用局部对象的析构函数 释放堆内存和系统句柄（就是文件描述符这种的，内核是通过句柄来找到结构体和资源的）  然后再回收栈内存
   ```

5. CPU为什么要靠**RSB**（Return Stack Buffer) 来“猜测”返回地址？  RSB遇到call的时候 CPU一边往物理内存栈压入返回地址  一边还要在RSB中备份一份。遇到ret的时候 直接从RSB弹出一个地址**供流水线执行** 不用等待慢吞吞的内存访问  之后**后台再校验是否跟内存里面的返回地址一样** 如果**猜对了**的话 **流水线满速前进**。如果**猜错了**的话（深度递归导致RSB溢出 或者栈被破坏）触发**流水线清仓** 直接浪费几十个时钟周期

6. 为什么函数调用会拖慢流水线？

   1. **指令缓存失效**  顺序执行的代码具有极高的**空间局部性** 命中率极高  但是如果发生非内联的函数跳转的话 极易使指令缓存失效
   2. **分支预测**容易**失效**  因为调用的地址动态多变（尤其是虚函数调用）  极易预测失败



##### 内联

###### 详解

通过上述第6点来看  内联的作用就显现出来了

1. 空间连续  代码直接嵌入调用处  **消除**压栈、出栈、修改寄存器的**开销**

2. **喂饱预取器**(CPU执行指令不是每条都从内存现读的 而是依靠指令缓存和分支预取器  普通调用**一会儿跳这一会儿跳那**的 容易让预取器预测失效 打乱流水线  ) **内联后**，所有机器指令在内存空间中**线性单向排布** 预取器可以全速将后续的指令预载到L1中  指令**物理排列连续** **消除指令缓存失效**

3. 打破**优化屏障**  三大**连锁优化**

   1. **常量折叠**  编译期，编译器直接计算出常量表达式的结果 以硬编码的数值写入汇编 而不是把计算过程留到程序运行的时候去消耗CPU。如果未内联的话 函数必须假设输入的参数是动态的变量 

   2. **死代码消除**    编译器分析某段代码在任何逻辑下都**绝对不可能被执行** 或者删掉这段计算结果根本**没有任何外部副作用**的话 会直接将整段代码从最终的二进制中彻底删掉

      ```c++
      enum class LogLevel { DEBUG, ERROR };
      inline void sensor_log(LogLevel level, const char* msg) {
          if (level == LogLevel::DEBUG) {
              // 昂贵的调试字符串拼装与打印
              do_heavy_debug_trace(msg); 
          }
      }
      // 实际生产代码中：
      void process_radar() {
          sensor_log(LogLevel::ERROR, "Radar check");
      }
      
      //编译器看到上下文是 if (LogLevel::ERROR == LogLevel::DEBUG)，这一判断恒为假。直接将整条 if 分支连同里面的 do_heavy_debug_trace 从最终机器码中彻底蒸发
      ```

   3. **SIMD循环向量化** （Single Instruction,Multiple Data，单指令多数据流） 传统标量运算 一次加法只能算一对float 现代CPU有超宽向量寄存器 一个256位寄存器可以并排塞入8个float 一个时钟周期内就能把8对浮点数加完

      如果是函数调用的话 会**破坏循环紧凑性** 打碎寄存器上下文 导致**编译器不敢开启向量化** 

      ```c++
      // 一个简单的限制数值范围（Clamp）函数
      inline float clamp_point(float val) {
          return val < 0.0f ? 0.0f : (val > 100.0f ? 100.0f : val);
      }
      
      // 在自动驾驶处理激光雷达（LiDAR）数十万个点云：
      void filter_point_cloud(float* points, int size) {
          for (int i = 0; i < size; ++i) {
              points[i] = clamp_point(points[i]);
          } //这样就能循环向量化
      }
      ```



###### 注意事项

1. **内联缺点：**  **代码膨胀**  反向导致L1缓存频繁爆仓 性能大跌
2. inline只是**建议** 如果太长的函数会拒绝内联  而短小的函数即使没写inline 开启优化的话也会强行自动内联
