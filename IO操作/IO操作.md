#### 标准IO与文件IO的区别

标准IO有缓冲区 是系统提供的库函数,文件IO没有缓冲区 会进行系统调用

线程安全性: 标准IO是线程安全的 内部带有互斥锁 多线程同时打印不会乱码  文件IO是原子性的 要自己加锁

#### 标准IO

##### EOF

```c++
#define EOF (-1)
```

在c语言标准库头文件里面 EOF等价于-1

但是为什么标准IO函数失败的时候一定要返回EOF而不是直接返回-1呢?

1. 语义化(可读性)  返回EOF能清晰地告诉别人 数据读到末尾了 或者IO操作失败/出错了
2. 跨平台与规范统一  首先这是标准IO库统一的  其次就是 如果真的有极少数EOF不等于-1 而是等于其他别的什么数  业务代码也不用改 只要写的都是EOF 重新编译之后就能完美运行

#### 单字符读写

###### fgetc

```c++
#include <stdio.h>
int fgetc(FILE *stream);
功能：从指定文件中读取一个字符数据，并以无符号整数的形式返回
参数：文件指针
返回值：成功返回读取的字符对应的无符号整数，失败返回EOF并置位错误码
```

**为啥要返回int?**

因为如果用char类型的变量来接收fgetc的结果的话 比如字符的值是255 如果是int 就会把255放到4个字节里面 前面都是0 是正数 就能表示出正常的字符 但是如果用char来接收的话 由于char一般都是signed char,前3个字节的0被截断了 第一个数为1 代码就会以为这是个负数 从而出现-1  并且-1刚好就是EOF的值 就会导致退出循环  所以接收fgetc的变量类型只能是int  (用unsigned char接受也不行 因为-1会被弄成255 导致接收的值永远不会等于EOF 进而死循环)

##### 标准IO的缓冲区问题

###### 行缓冲

跟终端文件相关  文件指针:stdin stout

大小:1024字节

###### 全缓冲

跟外界文件相关  文件指针:fp (fwrite fread操作)

大小:4096字节

###### 不缓冲

跟标准出错相关  文件指针:stderr

大小:0

##### 缓冲区的刷新时机

###### fflush

```c++
#include <stdio.h>
int fflush(FILE *stream);
功能：刷新给定的文件指针对应的缓冲区
参数：文件指针
返回值：成功返回0，失败返回EOF并置位错误码
```

###### 行缓冲刷新时机

1. 遇到换行符
2. 缓冲区满1024字节
3. 手动fflush / fclose(stdout) / **程序正常退出**
4. 在stdin读数据前会自动刷出stdout的行缓冲

###### 全缓冲刷新时机

1. 缓冲区满4096字节
2. 手动fflush / fclose(fp) / **程序正常退出**

###### 无缓冲刷新时机

1. 即时刷新

##### 缓冲刷新注意事项

1. 程序正常退出的时候 会自动刷新行缓冲和全缓冲里面的剩余数据 但是如果**程序异常崩溃**的话 **行缓冲或者全缓冲里面的数据会直接丢失** 所以这就是为什么调试信息之类的要用stderr / fprintf(stderr,...)来打印 而不是用printf
2. 重定向机制  stdout如果是屏幕显示的话是行缓冲 但是如果运行程序的时候进行了重定向 比如./app>log.txt stdout会被提升为全缓冲 此时遇到\n也不会立即刷新
3. fork()之前一定要fflush一下 不然的话父子进程结束的时候会把之前缓冲区里面的内容写出两次

##### \0与\n的末尾添加

首先 这个是**只有行缓冲才有的概念** 全缓冲根本不管什么\n或者\0

1. fgets 空间足够的话包含\n  自动加\0
2. scanf("%s",...) 忽略开头空白 遇到\n tab 或者空格停止且丢弃(是丢在缓冲区 会影响下一次getchar)  自动添加\0 但是比较**危险**  如果输入的字符超过数组容量 会导致缓冲区溢出
3. getline 包含\n 自动添加\0  非常安全 内部动态malloc
4. read 包含\n 不会自动添加\0 因为是原始字节流

#### 文件IO

主要的标识就是文件描述符  也就是FILE结构体里面的 _fileno

##### 文件打开与关闭

###### open

```c++
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
 int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);
功能：打开或创建一个文件，并返回该文件的文件描述符，返回文件描述符的规则是最小未分配原则
参数1：要打开的文件文件路径
参数2：打开模式
以下三种方式必须选其一：O_RDONLY(只读)、O_WRONLY（只写）、O_RDWR（读写）
以下的打开方式可以有零个或多个，跟上述的方式一起用位或运算连接到一起
O_CREAT:用于创建文件，如果文件不存在，则创建文件，如果文件存在，则打开文件，如果
flag中包含了该模式，则函数的第三个参数必须要加上
O_APPEND:以追加的形式打开文件，光标定位在结尾
O_TRUNC:清空文件
O_EXCL:常跟O_CREAT一起使用，确保本次要创建一个新文件，如果文件已经存在，则open
函数报错
eg:
"w": O_WRONLY|O_CREAT|O_TRUNC
"w+": O_RDWR|O_CREAT|O_TRUNC
"r": O_RDONLY
"r+": O_RDWR
"a": O_WRONLY|O_CREAT|O_APPEND
"a+": O_RDWR|O_CREAT|O_APPEND
参数3：如果参数2中的flag中有O_CREAT时，表示创建新文件，参数3就必须给定，表示新创建的
文件的权限
如果当前参数给定了创建的文件权限，最终的结果也不一定是参数3的值，系统会用你给
定的参数3的值，与系统的umask取反的值进行位与运算后，才是最终创建文件的权限（mode & ~umask）
当前终端的umask的值，可以通过指令 umask 来查看，一般默认为为 0022，表示当
前进程所在的组中对该文件没有写权限，其他用户对该文件也没有写权限
当前终端的umask的值是可以更改的，通过指令：umask 数字进行更改，这种方式只对
当前终端有效
普通文件的权限一般为：0644，表示当前用户没有可执行权限，当前组中其他用户和其
他组中的用户都只有读权限
目录文件的权限一般为：0755，表示当前用户具有可读、可写、可执行，当前组中其他
用户和其他组中的用户都没有可写权限
    (目录文件就是目录 ls对应读 新增普通文件代表写 cd或者cat代表可执行)
注意：如果不给权限，那么当前创建的权限会是一个随机值(未初始化垃圾数据)
返回值：成功返回打开文件的文件描述符，失败返回-1并置位错误码
```
